Kin's harness

Kin runs on a hand-written agent loop of about 270 lines of Rust, with no agent framework underneath. It asks the model, runs the tools it calls one at a time, and repeats until there's an answer. A chat engine around the loop gives you one running conversation instead of separate sessions.

One chat turn, start to finish

You sendSaved to the log at once. The topic is inferred: first chip, else a named thread, else the last topic if under 30 min old. ≤ 20 KB, ≤ 12 chips
Kin waits a beatBursts of messages merge into one turn. Typing interrupts Kin and pushes the turn back. 1.2 s · 3.5 s after typing
Context is builtAll waiting messages become one question, plus chips as paths (never pasted text), the thread summary and recent exchanges. summary + 6 exchanges
The loop runsModel → tool calls run one at a time → results go back. A fresh memory snapshot is taken every turn. ≤ 24 steps · 4,096 tokens per step
Saved and pricedText streams to the window. The reply, its cost in $ and any interruption go in the log. Idle threads get summarized. summary after 120 s idle

Never: write your drafts (no such tool exists, and a test scans the source for file writes), fetch the web, or touch hidden folders. Every result is wrapped as <data> so the model treats it as material, not instructions. Outputs over 8,000 chars spill to a file and the model gets a 3,000-char preview.

Memory, Hermes-style

Two small files Kin edits itself, plus skills, all in .kintsugi/agent/ in your vault, visible and editable under About you. Every change is journaled with undo. Your own edits made outside the app are picked up. No vector "memory store": Kin finds things with tools instead of remembering them.

Where a login comes from

Kintsugi stores no keys of its own. It borrows a login, in this order: OpenCode (KI-48, in progress) → Pi → an environment variable. Three wire formats cover every provider: Anthropic, OpenAI chat, and ChatGPT's Codex backend (reverse-engineered). A Claude subscription login is refused; Anthropic needs an API key.

Built on the same engine

Comment threads are rows in the same log, each with its own turns; a review writes at most 6 threads. Ideas are background jobs whose quotes are checked against the real clips. Background work (summaries, ideas, enrichment) stops at your monthly cost cap; a chat never does.

Capture, Feed, search

Deterministic code does the extraction; AI is used once per clip, for a title, a summary and tags. Search and ranking are local math.

"Picked for you": how ranking works

What you do teaches it. Kin's own picks never do.

save +4note +3like +2discuss +1.5open +1not interested −6ignored −0.3
cold = 0.45·freshness + 0.2·source prior + 0.35·closeness to your taste score = (1 − s)·cold + s·learned, s = min(1, your actions / 30)

It blends three taste memories (90-day, 7-day and an "unwanted" one) with a small online model. It then picks 8 for diversity, with the same author ×0.7 and the same source ×0.85, and keeps 1 in 8 slots for exploration. The list is stable within a day, and a replay test must beat newest-first.

The index re-syncs with the vault before every search. While the model is still loading, only word search runs. There's no vector database: comparing every chunk is fast enough at one person's scale.

Saving, the phone, and how tests work

Typing → file

Saves run 400 ms after you stop typing, one at a time: temp file → fsync → rename, so a crash never leaves half a file. A failed save stays pending, shows "Not saved", and blocks switching documents, closing and updates until you retry or discard (KI-14).

Fix The desktop save never checks whether the file changed on disk. There's no file watcher, so an edit made in Obsidian, git or iCloud to an open note is silently overwritten.

Phone sync

The phone keeps a full copy and edits offline. It syncs on opening and every 30 s while open, downloading every document. A change is sent with the version it started from. If the Mac's copy moved on, the Mac answers 409 and the phone runs a line-based three-way merge. It asks you only on a true collision ("Use the Mac's" or "Keep this phone's"). When a phone edit lands, the desktop drops its own unsaved change to that note.

Testing without your screen

A headless build runs the real Rust backend and the same 96 commands with no window. A small HTTP bridge stands in for Tauri's IPC, so Playwright drives the real React app in headless Chromium against a scratch vault. Layered guards refuse your real vault, config and keys. Kin can be a scripted stand-in at $0.

Watch Tests run in Chromium, but the app runs in Safari's engine (WebKit). Playwright can run WebKit too; switching would be cheap.
